# T13. 의도치 않은 쓰기 명령 실행

> 상태: Accepted (Phase 2 게이트, 2026-11-05, #457에서 [security-review.md](../security-review.md) §2를 위협별로 나눔) · 관련: [security-review.md](../security-review.md) (범위·가정 §1, 최종 규칙 §3, 실험 기록 §4, 체크리스트 §5, S-05 근거 §6)

- **설명**: 조회 앱이 버그나 잘못된 구현으로 쓰기 명령을 실행하는 문제다.
- **대응**:
  - **컴파일 타임 allowlist**: `ReadOnlyGitCommand`와 `FetchCommand` case만 존재한다. 쓰기 명령은 타입이 없다 ([카탈로그 §7](../../architecture/git-command-catalog.md)). gh·glab·gt도 조회 명령 case(`GHCommand`, `GLCommand`·`GTCommand`, ADR-0026)만 있다.
  - **프로세스 생성 위치 제한**: `Overgrove/Execution/` 밖에서 `Process`를 만들면 안 된다. `scripts/lint/check-forbidden-apis.sh`가 pre-commit hook, Claude Code hook, CI에서 검사한다.
  - **index 쓰기 방지**: `--no-optional-locks`와 `GIT_OPTIONAL_LOCKS=0`으로 조회 중 `index.lock`을 잡지 않는다. `git diff`는 이 설정을 무시하고 stat만 바뀐 경로의 index를 새로 고쳐 쓰므로, 공통 인자 `-c diff.autoRefreshIndex=false`로 막는다 (확인, #208). 이 인자는 diff 계열이 아닌 명령에는 영향이 없어 공통 인자에 둔다.
  - **허용된 쓰기**: fetch가 만드는 쓰기(`refs/remotes/<원격>/*`, `FETCH_HEAD`, 객체)와 `--prune`의 원격 추적 ref 삭제뿐이다.
  - **fetch 범위 고정(#209)**: 저장소 설정이 이 범위를 넓히지 못하게 fetch 인자에 고정한다. refspec `+refs/heads/*:refs/remotes/<원격>/*`와 `--refmap=`, `--no-tags`, `-c fetch.pruneTags=false -c remote.<원격>.pruneTags=false -c fetch.bundleURI=`를 쓴다([카탈로그 §4](../../architecture/git-command-catalog.md)). 고정하기 전에는 로컬 `remote.<n>.fetch=+refs/heads/*:refs/heads/*`(detached HEAD)가 로컬 브랜치를 지우고 `main`을 되돌렸다. 로컬 `fetch.pruneTags`는 로컬 태그를 지웠다(#206 보안 검토, E40).
- **잔여 위험**: 낮음. #94의 테스트와 리뷰에서 찾은 두 결함, `git diff`의 index 쓰기(#208)와 저장소 설정에 의한 fetch 범위 확대(#209)는 고쳤다.
  - `--no-tags` 때문에 원격에만 있는 새 태그는 v0.1에서 가져오지 않는다(의도된 동작, #209).
- **검증**:
  - SEC-T13-01 (모든 case의 서브커맨드가 허용 집합 안에 있음)
  - SEC-T13-02 (status 조회 전후 `.git/index` 내용·mtime 불변, 연결 워크트리 포함. stat만 바뀐 파일의 worktree diff와 기준 브랜치 비교(`git diff --merge-base`, 작업 트리 포함, #157)도 불변이고, `diff.autoRefreshIndex=false`를 빼면 다시 쓰는 대조군 포함. 다른 조회는 `.git` 전체 불변까지 확인)
  - SEC-T13-03 (금지 API 정적 검사. 저장소 전체 통과와 함께, 심은 위반을 실제로 거부하는지 테스트로 확인)
  - SEC-T13-04 (로컬 `remote.<n>.fetch`·`fetch.pruneTags`·`remote.<n>.pruneTags`·`tagOpt`·`fetch.bundleURI`를 심은 저장소에서 앱 fetch 뒤 `refs/remotes/` 밖의 모든 ref와 HEAD 불변, 대조군(고정 전 인자)에서는 브랜치·태그 삭제, `main` 이동, `refs/bundles/*` 생성)
  - SEC-T13-05 (이슈의 `Open in Browser`는 정확히 `https://github.com/OWNER/NAME/issues/<번호>`일 때만 `NSWorkspace`에 넘김. 다른 번호·`pull`·경로 추가·쿼리·조각·사용자 정보·포트 거부, #81)
  - SEC-T13-06 (실제 git: 저장소 밖 위치를 가리키는 `extensions.refStorage`는 보고되고 앱이 fetch하지 않으며 밖에 아무것도 쓰지 않음. 대조군인 평범한 git 2.54는 밖에 ref와 reflog를 씀. 이 확장을 모르는 git은 git 디렉터리를 무시해 저장소 명령이 스스로 실패함, #356)
  - SEC-T13-07 (저장소 로컬 `transfer.bundleURI`는 T13으로 보고하고, 서버가 bundle URI를 광고해도 앱 fetch와 그냥 fetch 모두 따르지 않음. clone 대조군은 따름, #195)
  - SEC-T13-449-1 (gt 버전 줄(`gt version X.Y.Z`)이 아니거나(Graphite CLI 등 다른 도구) 최소 버전 1.1.0 미만이면 `--version` 밖의 명령을 실행하지 않음, ADR-0026 §6)
  - SEC-T13-449-2 (gt: 버전 확인·auth status·issue list를 거친 한 번의 로드 전후로 gt의 HOME·TMPDIR·중립 폴더 파일 트리가 같음. 기본은 대역, `OVERGROVE_TEST_GT`로 실제 gt를 줄 수 있음. 실제 gt 1.1.0도 계정 없는 상태에서 파일을 만들지 않음을 확인, ADR-0026 §6)
- **상태**: 설계 완료 (정적 검사 스크립트는 저장소 셋업에서 적용)
