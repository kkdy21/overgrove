# T8. fetch 중 자동 gc·maintenance

> 상태: Accepted (Phase 2 게이트, 2026-11-05, #457에서 [security-review.md](../security-review.md) §2를 위협별로 나눔) · 관련: [security-review.md](../security-review.md) (범위·가정 §1, 최종 규칙 §3, 실험 기록 §4, 체크리스트 §5, S-05 근거 §6)

- **설명**: fetch가 끝나면 git이 `git maintenance run --auto`를 실행한다 (확인: `GIT_TRACE`). 이 작업은 객체를 다시 묶고 prune하는 쓰기 작업이고, 큰 저장소에서 오래 걸린다.
- **시나리오**: 조회 앱이 사용자 모르게 저장소 정리를 시작한다. 그동안 사용자의 다른 git 작업과 잠금이 충돌한다.
- **대응**: 공통 인자 `-c gc.auto=0 -c maintenance.auto=false` (확인: maintenance가 실행되지 않음). fetch의 `--no-auto-maintenance` 옵션도 2.50에서는 받아들여지지만, 도입 버전을 확인하지 못해 쓰지 않는다.
- **잔여 위험**: 없음.
- **검증**:
  - SEC-T8-01 (로컬 `gc.auto=1`·`maintenance.auto=true` 픽스처를 `GIT_TRACE=1`로 fetch했을 때 자식 프로세스에 `maintenance run`과 `gc --auto`가 없음. pack 수 비교는 alternates가 있으면 변하지 않아 판정에 쓰지 않는다, [fixtures.md §8.3](../../testing/fixtures.md))
  - SEC-T8-02 (인자 스냅샷)
- **상태**: 설계 완료
