# T17. 공급망

> 상태: Accepted (Phase 2 게이트, 2026-11-05, #457에서 [security-review.md](../security-review.md) §2를 위협별로 나눔) · 개정: 2026-11-17 Homebrew bottle 항목 추가([ADR-0027](../../adr/0027-homebrew-bottles-in-personal-tap.md), #694) · 관련: [security-review.md](../security-review.md) (범위·가정 §1, 최종 규칙 §3, 실험 기록 §4, 체크리스트 §5, S-05 근거 §6)

- **설명**: 의존성이나 CI Action이 오염되면 빌드 산출물이나 저장소 비밀이 위험해진다. Homebrew bottle(ADR-0027)은 사용자에게 바로 실행되는 바이너리라, 그 빌드 경로가 오염되면 사용자의 Mac이 위험해진다.
- **대응**:
  - 외부 패키지 0개 (ADR-0006)
  - GitHub Actions는 전체 커밋 SHA로 고정하고 Dependabot으로 갱신한다.
  - 워크플로우 `permissions:`는 최소로 둔다.
  - `pull_request_target`은 보드 동기화(`board-sync.yml`, ADR-0016) 한 곳에서만 쓴다. 지키는 조건은 다음과 같다.
    - 기본 브랜치만 체크아웃하고(`persist-credentials: false`) PR 코드는 체크아웃하거나 실행하지 않는다.
    - 이벤트에서는 이슈·PR 번호만 쓴다.
    - 메인테이너가 아닌 사람의 이벤트는 동시성 그룹 하나를 공유한다.
    - PR은 자기 브랜치 이름의 이슈를, 그 이슈를 가진 사람이 낸 경우에만 움직인다.
  - 보드 토큰 `PROJECT_TOKEN`은 `project` scope 하나만 가진 classic token이다. 보드 #4에만 쓰기 권한이 있는 전용 머신 계정의 토큰을 권장한다.
  - PR 제목·본문 같은 신뢰할 수 없는 값은 `env:`로만 넘긴다.
  - CI의 gitleaks는 버전과 SHA-256을 고정해 받는다.
  - Homebrew bottle([ADR-0027](../../adr/0027-homebrew-bottles-in-personal-tap.md))은 개인 tap `kkdy21/homebrew-tap`의 GitHub Actions 워크플로우가 태그 소스에서 빌드한다. 메인테이너의 Mac에서 만든 bottle은 올리지 않는다. 워크플로우 원본은 `packaging/homebrew/.github/workflows/bottle.yml`이다.
    - Action은 전체 커밋 SHA로 고정하고 tap의 Dependabot이 갱신한다. 트리거는 `workflow_dispatch` 하나다.
    - 최상위 권한은 `contents: read`다. 빌드 job은 `id-token: write`와 `attestations: write`만 더하고, Release를 만드는 job만 `contents: write`를 갖는다.
    - `actions/attest`로 bottle의 build provenance attestation을 남긴다. 사용자는 `HOMEBREW_VERIFY_ATTESTATIONS=1 brew install …`이나 `gh attestation verify … --repo kkdy21/homebrew-tap`으로 확인한다(README).
    - formula가 소스 tarball과 bottle의 sha256을 고정한다. 공개한 bottle 파일은 바꾸지 않고, 다시 만들면 `rebuild`를 올린다.
    - bottle을 믿지 않는 사용자는 `brew install --build-from-source`로 같은 formula를 소스에서 빌드한다.
  - git 호환성 매트릭스(`git-compat.yml`, [ADR-0020](../../adr/0020-git-compatibility-matrix-in-ci.md))는 최소 지원 버전 git을 kernel.org 공식 tarball에서 버전과 SHA-256을 고정해 받는다. 해시가 맞을 때만 러너 안에서 빌드하고, 테스트에만 쓰며, 캐시하지 않는다. 필수 검사가 아니고 `contents: read` 권한만 쓴다. Homebrew git은 러너에 있는 것만 쓰고 새로 설치하지 않는다.
- **잔여 위험**:
  - Apple 툴체인과 GitHub 러너 이미지는 신뢰한다.
  - 보드 토큰이 새면 그 계정이 쓸 수 있는 모든 Projects 보드가 바뀔 수 있다. 메인테이너 계정 토큰이면 메인테이너가 속한 조직의 보드도 포함된다. 저장소 코드와 이슈는 영향이 없다.
  - `pull_request_target`은 첫 기여자 승인 없이 실행된다. 외부 사용자가 이벤트를 많이 만들면 토큰 계정의 API 한도를 쓸 수 있다. 공유 동시성 그룹으로 상한을 둔다.
  - bottle은 ad-hoc 서명이라 macOS가 출처를 확인하지 않는다. Homebrew는 formula 다운로드에 격리 표시를 붙이지 않아 Gatekeeper도 보지 않는다. attestation 확인은 사용자가 켜야 한다. attestation은 "그 tap 저장소의 워크플로우가 만들었다"까지만 보증한다. 메인테이너 계정이나 tap 저장소가 탈취되면 formula와 워크플로우를 함께 바꿀 수 있다.
  - bottle 빌드는 GitHub의 macOS 러너 이미지, 거기 있는 Homebrew와 Xcode를 신뢰한다.
  - tap 워크플로우는 이 저장소의 `scripts/lint/check-workflows.sh`가 보지 않는다. 릴리스 때 `packaging/homebrew/`의 사본과 같은지 손으로 확인한다.
  - 호환성 매트릭스의 tarball 해시는 워크플로에 적힌 값이 신뢰의 기준이다. CI는 kernel.org 서명을 검증하지 않는다. 해시를 바꾸는 PR이 출처(`sha256sums.asc`)를 밝히고 리뷰를 거친다(ADR-0020 §4).
- **검증**:
  - SEC-T17-01 (SPM 의존성·`Package.resolved` 없음 — `scripts/lint/check-no-dependencies.sh`와 그 테스트, CI `build-test`)
  - SEC-T17-02 (워크플로우의 모든 `uses:`가 40자리 SHA로 고정. 같은 검사가 다음도 확인한다: 모든 워크플로우에 최상위 `permissions:`가 있고 `write-all`이 없음, `pull_request_target`은 `board-sync.yml`에만, PR·이슈 제목·본문·브랜치 이름 같은 신뢰할 수 없는 값은 `KEY: ${{ … }}` 매핑(`env:`)으로만, CI gitleaks 다운로드의 버전·SHA-256 고정 — `scripts/lint/check-workflows.sh`와 그 테스트, CI `build-test`, #95)
  - SEC-T17-03 (Dependabot이 `/`의 `github-actions`를 갱신 — 같은 스크립트)
  - SEC-T17-04 (`git-compat.yml`의 테스트용 git: kernel.org tarball만, `TEST_GIT_VERSION`·`TEST_GIT_SHA256` 고정, 주석이 아닌 줄에서 `TEST_GIT_SHA256`으로 검증하고 그 검증이 압축 해제·빌드보다 앞, `actions/cache` 없음 — `scripts/lint/check-workflows.sh`와 그 테스트, ADR-0020), 보드 상태 규칙은 `scripts/github/board-sync-rules.test.sh`(CI `build-test`). **수동**: `PROJECT_TOKEN`이 `project` scope 하나만 가진 토큰인지는 CI에서 볼 수 없어 메인테이너가 토큰을 바꿀 때 확인한다
  - **수동(Homebrew bottle)**: [release-checklist.md §8](../../qa/release-checklist.md#8-태그-뒤-homebrew-tap)에서 릴리스마다 확인한다. tap 워크플로우의 SHA 고정과 권한, bottle sha256, `gh attestation verify`, 설치된 앱에 격리 표시가 없는지, 소스 빌드 대체 경로다
- **상태**: 적용됨 (저장소 셋업: 워크플로우와 Dependabot, SEC-T17-01은 #33에서 CI에 추가)
