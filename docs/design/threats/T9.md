# T9. 인자 인젝션

> 상태: Accepted (Phase 2 게이트, 2026-11-05, #457에서 [security-review.md](../security-review.md) §2를 위협별로 나눔) · 관련: [security-review.md](../security-review.md) (범위·가정 §1, 최종 규칙 §3, 실험 기록 §4, 체크리스트 §5, S-05 근거 §6)

- **설명**: 파일명이나 ref 이름이 옵션(`--output=...`)이나 pathspec 매직(`:(exclude)`, glob `*`)으로 해석되는 문제다.
- **시나리오**: `--output=../../x`라는 이름의 파일이나 ref를 인자로 넘기면 git이 파일을 쓴다. `*`라는 파일명의 이력을 보면 glob으로 해석되어 다른 파일 이력이 섞인다 (확인: glob이 모든 파일과 일치).
- **대응**:
  1. 셸을 쓰지 않는다. 인자는 배열로만 넘긴다 (ADR-0008).
  2. 경로는 항상 `--` 뒤에 둔다.
  3. 공통 인자 `--literal-pathspecs`로 pathspec 매직을 끈다 (확인).
  4. 커밋은 검증된 OID(`^[0-9a-f]{40}$|^[0-9a-f]{64}$`)로만 가리킨다. stash도 `stash@{n}`이 아니라 OID로 가리킨다.
  5. ref는 `refs/`로 시작하는 전체 이름만 인자로 쓴다. 제어 문자, 공백, `..`, `-` 시작 구성 요소가 있으면 거부한다.
  6. 리비전 인자 앞에 `--end-of-options`를 둔다. `log`, `rev-list`, `diff-tree`, `stash show`, `fetch`에서 동작을 확인했다.
  7. `git check-ref-format`은 `--` 구분자를 지원하지 않아(확인) 검증에 쓰지 않는다. 검증은 앱 코드에서 한다.
  8. gh 출력의 값으로 앱의 대상을 정하지 않는다. PR 상태(v0.2.0, ADR-0023)는 고정 인자의 `gh pr list --repo OWNER/NAME` 하나로 읽고, PR을 로컬 브랜치에 잇는 것은 head 저장소 소유자·이름과 브랜치 이름이 모두 브랜치의 upstream 원격과 맞을 때뿐이다. 브랜치 이름만으로 잇지 않는다(fork PR 사칭). 소유자·저장소 이름은 ASCII 대소문자 무시, 브랜치 이름은 바이트로 비교하고, head 저장소가 null이거나 비어 있는 PR(fork를 지운 PR 등)은 어디에도 잇지 않되 목록 전체를 실패로 보지 않는다. PR 제목·기준 브랜치 이름은 표시 전에 이스케이프하고(head 로그인·브랜치 이름은 화면에 쓰지 않는다), PR URL은 조회한 저장소의 `https://github.com/OWNER/NAME/pull/<그 번호>`일 때만 연다. 잔여 위험: 잇기는 저장소 설정(`remote.<n>.url`)을 믿는 만큼만 믿을 수 있다(조회 대상이 이미 그 설정으로 정해지는 이슈 패널과 같다). 검증은 SEC-T9-06·07(#115).
- **잔여 위험**: 낮음. 모든 인자는 git 출력에서 온 값이고, 사용자가 직접 입력하는 값(검색어)은 git에 넘기지 않는다.
- **검증**:
  - SEC-T9-01 (모든 case의 최종 인자 배열 스냅샷. 기준 브랜치 비교의 기준 ref는 `--end-of-options` 뒤, 파일은 `--` 뒤, #157. 두 커밋 사이 커밋 목록의 범위는 검증된 OID 두 개의 `base..target`이고 `--end-of-options` 뒤, #389)
  - SEC-T9-02 (ref 검증: `-x`, `refs/heads/a..b`, 제어 문자 거부)
  - SEC-T9-03 (파일명 `-x`, `--output=x`, `:(exclude)x`, `*`로 diff·이력 → 해당 파일만 대상, 부수 파일 생성 없음)
  - SEC-T9-04 (OID 검증)
  - SEC-T9-05 (원격 URL → gh `--repo` 값: github.com 세 형식의 `OWNER/NAME`만. `-` 시작·비ASCII·userinfo·포트·다른 호스트·경로 추가 거부, #81)
  - SEC-T9-06 (PR 잇기: 같은 이름의 fork PR·저장소 이름만 다른 PR은 잇지 않음, fork 흐름은 fork 원격과 맞음, 소유자·이름은 ASCII 대소문자만 무시하고 전각 문자는 다름, 브랜치는 NFC/NFD까지 바이트 비교, 로컬 이름이 아니라 원격 ref로 맞춤, `/`가 든 원격 이름, upstream 없음·로컬 upstream·github.com 밖 원격·`refs/heads/` 밖 ref는 잇지 않음, head 없는 PR은 건너뛰고 다른 PR은 유지, ADR-0023 §4)
  - SEC-T9-07 (적대적 PR JSON: 번호·상태·URL이 틀린 항목과 배열 아닌 항목은 그 항목만 버림, head가 없거나 null·빈 값이면 목록에 두되 잇지 않음, 제목·기준 브랜치의 제어·bidi 문자 이스케이프, Open in Browser는 조회한 저장소의 그 번호 PR 주소일 때만, ADR-0023 §3)
- **상태**: 설계 완료
