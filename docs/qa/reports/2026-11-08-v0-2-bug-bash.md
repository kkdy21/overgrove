# v0.2 기능 통합 bug bash 보고 (2026-11-08)

> 상태: 보고 · 관련: #409, #100(v0.1 bug bash), [process.md](../process.md), [bug-triage.md](../bug-triage.md), [security-review.md](../../design/security-review.md)

v0.2 범위의 기능이 서로 만나는 지점을 `main` 기준으로 함께 점검했다. 대상 기능은 그래프 스트리밍(#254), 자동 새로고침(#275), 그래프 캐시와 히스토리 상태 처리(#333, #373), 신뢰하지 않는 저장소 모드(#107), 서브모듈 상태(#108), stash 노드(#393), 태그 섹션(#379), S-11/S-12(#390, #394)다. 찾은 결함은 하나씩 이슈로 등록했고, 이 PR에서는 고치지 않는다.

## 1. 요약

- **결함 24건**을 등록했다(모두 v0.2.0 마일스톤, `type:bug`, `phase:qa`). 우선순위는 **p1 2건**, p2 22건이다.
  - p1: #410(새로고침이 다음 페이지 읽기와 겹치면 그래프가 멈춤), #416(HEAD만 바뀌면 워크트리 목록을 다시 읽지 않아 브랜치 제목과 그래프가 오래됨)
  - 보안 1건(#423, p2): 공개 본문에 재현 상세를 적지 않았고, 상세는 담당자에게 따로 전달했다.
- **보안 결함은 그 밖에 없다.** 신뢰하지 않는 모드는 의도한 두 가지(fetch의 `file` 전송 금지, 터미널 열기 전 확인)만 바꾸고, status·서브모듈·그래프 페이지·스트림·#373 확인·비교는 모드와 관계없이 같은 하드닝 경로를 쓴다. 서브모듈 경로와 git 디렉터리 검증, 상한, 잘린 출력 처리도 맞았다.
- 가장 많은 결함은 **자동 새로고침(#275)과 다른 기능의 만남**에서 나왔다. FSEvents가 보는 변경(HEAD, refs, stash)과 새로고침 계획(`Plan`)이 다시 읽는 범위가 어긋나서, 화면 일부가 창 활성화나 ⌘R 때까지 오래된 채로 남는다(#416, #417, #420, #421, #426, #434).

## 4. 확인했고 문제없던 것

- **신뢰하지 않는 모드:** fetch 경로는 하나(`FetchController.start` → `GitClient.fetch`)이고 매번 플래그를 읽는다. 설정으로만 로컬이 되는 원격(`insteadOf` 등)도 `GIT_ALLOW_PROTOCOL`이 막는다. 모드에 따라 달라지는 캐시가 없으므로 토글 때 버릴 캐시도 없다.
- **서브모듈:** fetch는 `--no-recurse-submodules`, status·diff는 `--ignore-submodules=dirty`이고 중첩 서브모듈에 들어가지 않는다. 경로 검증(UTF-8 아님, 제어 문자, 절대 경로, `..`, 심볼릭 링크 거부)과 git 디렉터리 포함 검사, 상한과 잘린 출력 처리가 맞다.
- **그래프:** 스트림 페이지와 그 뒤의 `--skip` 페이지(중간에 commit-graph를 씀)의 순서가 같다(실험). stash 노드는 캐시 키 밖의 화면 겹쳐 그리기라서 페이지 캐시 때문에 겹치거나 빠지지 않는다. 중첩 annotated 태그는 끝까지 벗겨진다. 강제로 다시 단 태그는 ref 집합을 바꿔 그래프를 다시 읽게 한다.
- **S-11/S-12:** 저장소를 바꾸면 둘 다 닫히고 세대를 올린다. 늦게 온 결과는 버린다. 이력 이동(#381)은 없어진 대상을 건너뛴다. 같은 커밋 두 번, 순서, 병합·루트 커밋, 큰 목록 상한, UTF-8이 아닌 경로 처리가 맞다.
- **FSEvents:** bare 저장소와 바깥 연결 워크트리 감시, `/private`·`/var`·심볼릭 링크·대소문자 경로, 큰 저장소의 이벤트 폭주(`objects/`·`index.lock`·로그 무시, 10,000개 넘으면 rescan, 요청 하나와 재실행 간격), 앱 자신의 git 호출이 이벤트를 만들지 않음, 저장소 정리·창 닫기 때 스트림 정리가 맞다.
