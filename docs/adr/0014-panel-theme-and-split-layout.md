# ADR-0014: 메인 창은 자체 패널 테마와 사용자 정의 분할 레이아웃을 쓴다

> 상태: Accepted · 날짜: 2026-11-06 · 관련: #166, #159, [design/art-direction.md](../design/art-direction.md), [design/design-tokens.md](../design/design-tokens.md), [ADR-0010](0010-commit-graph-layout-in-app.md)

## 맥락

Phase 2 디자인은 "시스템이 먼저다"를 원칙으로 삼았다([design-tokens.md](../design/design-tokens.md) 이전 §1).

- 표면, 텍스트, 선택, 액센트는 macOS 시스템 색을 쓴다.
- 앱이 액센트 색을 정하지 않는다.
- 레이아웃은 `NavigationSplitView` 3단이다.

이 원칙으로 그린 #159 목업에 대해 메인테이너가 다음과 같이 피드백했다(2026-11-06).

- 왼쪽·오른쪽 패널이 영역으로 분명히 보이지 않는다. GitKraken처럼 박스로 나뉘고, 스크롤되고, 잡아서 크기를 조절할 수 있어야 한다.
- 그래프 색이 흐리다. GitKraken 쪽처럼 선명해야 한다.
- 전체 인상이 GitLens(VS Code)와 같다. 그 UI, 색, 구성을 선호하지 않는다.

원인은 원칙 자체에 있었다. macOS 시스템 색의 다크 모드 근삿값(`#1e1e1e`, `#2a2a2a`)은 VS Code Dark+의 회색과 거의 같다. 또 `NavigationSplitView`의 사이드바 재질과 분할선은 둥근 상자, 홈, 손잡이로 꾸밀 수 없다.

## 결정

메인 창은 **자체 패널 테마(Slate)와 사용자 정의 분할 컨테이너**를 쓴다. 네이티브 동작(메뉴, 시트, 팝오버, 설정 창, 포커스 링, 단축키, VoiceOver)은 그대로 둔다.

1. **표면·텍스트·테두리**는 앱 고유 토큰 `primitive.color.slate.*`에서 고른다. 라이트·다크 값을 모두 앱이 정한다. 시스템 색은 네이티브 컨트롤과 창 버튼에만 남는다.
2. **액센트**는 앱 아이콘에서 가져온 Grove 초록(`forest.400` / `forest.700`)이다. 앱의 AccentColor로 등록한다. 사용자가 시스템 설정에서 액센트 색을 직접 골랐으면 macOS가 그 색으로 바꾸는 표준 동작을 따른다.
3. **레인 팔레트**는 다크 캔버스 위에서 선명한 고채도 8색으로 새로 만든다. 레인 색 결정 규칙(열 인덱스 mod 8, ADR-0010 §4)은 바꾸지 않는다.
4. **레이아웃**은 `NavigationSplitView` 대신 사용자 정의 분할 컨테이너다. 세 패널은 둥근 상자이고, 그 사이 8pt 홈이 크기 조절 손잡이다. 분할 규칙은 다음과 같다.
   - 최소·최대 폭이 있다.
   - 더블클릭하면 기본 폭으로 돌아간다.
   - 최소 폭보다 더 끌면 사이드바와 상세가 접힌다.
   - 폭은 저장소마다 기억한다.
   - 표준 단축키(`⌃⌘S`, `⌥⌘0`)를 직접 연결한다.
   - 상세 규칙은 [art-direction.md §3](../design/art-direction.md#3-창-구조)과 [interaction.md §2.1](../design/interaction.md#21-패널-크기-조절과-스크롤)에 있다.
5. 다른 제품의 색 값, 아이콘, 문구는 쓰지 않는다. GitKraken에서는 배치 패턴만 참고한다(HANDOFF 원칙).

## 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 시스템 색 유지 + 레인 색만 교체 | 다크 모드·Increase Contrast·액센트가 자동 대응 | 패널이 여전히 VS Code처럼 보이고 상자 구분이 약함 | 피드백의 핵심(영역, 인상)을 해결하지 못함 |
| `NavigationSplitView` + 열 안에 상자 그리기 | 표준 분할선, 접기 동작 무료 | 사이드바 재질과 분할선 모양을 바꿀 수 없음. 상자 사이 홈과 손잡이를 둘 수 없음 | 상자 레이아웃과 시각적으로 충돌 |
| `HSplitView` | AppKit 분할선, 구현 간단 | 분할선 굵기·모양, 접기, 폭 저장을 제어하기 어려움 | 손잡이 디자인과 접기 규칙을 구현할 수 없음 |
| GitKraken 색 값 사용 | 메인테이너가 원한 인상과 가장 가까움 | HANDOFF 원칙 위반, 상표·트레이드 드레스 위험 | 원칙 위반. 같은 성질의 자체 팔레트로 대체 |

## 결과

- 좋아지는 점
  - 영역이 분명하고, 크기를 조절할 수 있다는 것이 눈에 보인다.
  - 레인 색이 워크트리 타일, 알약, 툴바 칩으로 이어져 "워크트리 ↔ 그래프 줄"이 색으로 연결된다.
  - 라이트·다크 대비를 모두 앱이 검증한다(`colorcheck.py`).
- 나빠지는 점, 감수하는 비용
  - Increase Contrast와 향후 OS 외형 변화에 앱이 직접 대응해야 한다. 고대비 변형을 Asset Catalog에 따로 둔다.
  - 분할 컨테이너, 접기, 폭 저장, 분할선 접근성(VoiceOver 조절)을 직접 구현하고 테스트해야 한다.
  - macOS 기본 앱과 외형이 다르다. 대신 동작과 단축키는 표준을 지킨다.
- 다시 검토해야 하는 조건
  - macOS가 사이드바·인스펙터 외형을 크게 바꿔 자체 테마가 어색해질 때
  - 사용자 정의 분할 컨테이너가 성능 예산(PB-2 워크트리 전환, PB-4 그래프 스크롤)을 넘을 때
