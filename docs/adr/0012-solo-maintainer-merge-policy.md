# ADR-0012: 1인 메인테이너 머지 정책 — PR과 CI는 필수, 승인 리뷰는 요구하지 않는다

> 상태: Accepted · 날짜: 2026-11-05 · 관련: HANDOFF §6.4, [process/pull-requests.md](../process/pull-requests.md), [process/github-settings.md](../process/github-settings.md)

## 맥락

HANDOFF §6.4는 `main` 보호 규칙으로 "필수 리뷰 1명 이상(본인 승인 불가)"을 적었다. 메인테이너가 한 명뿐이라 이 규칙을 그대로 걸면 메인테이너 자신의 PR을 영원히 머지할 수 없다. 그렇다고 우회(bypass)를 허용하면 보호 규칙이 형식에 그친다.

## 결정

`main` 브랜치 룰셋은 다음과 같이 둔다.

| 항목 | 설정 |
|---|---|
| PR 필수 | 예 (직접 푸시 금지) |
| 필수 승인 리뷰 수 | **0** |
| 필수 상태 검사 | `gitleaks`, `pr-policy`, `build-test` (모두 통과, 최신 상태 요구) |
| 머지 방식 | **squash 전용**. squash 커밋 제목은 PR 제목 |
| 강제 푸시 / 브랜치 삭제 | 금지 |
| 선형 이력 | 요구 |
| 우회 대상(bypass) | **없음** (관리자 포함) |
| 커밋 서명 | 권장, 필수 아님 |

리뷰 품질은 다음으로 보완한다.

1. PR 템플릿의 자체 점검 체크리스트 (테스트, 보안 영향, 문서, 스크린샷)
2. 보안 관련 변경은 Claude Code `security-reviewer` 에이전트 검토 결과를 PR 코멘트로 남긴다.
3. 외부 기여자 PR은 메인테이너가 리뷰하고 승인한 뒤에 머지한다. 규칙상 강제는 아니고 운영 원칙이다.
4. 공동 메인테이너가 생기면 필수 승인 수를 1로 올리고 이 ADR을 대체한다.

## 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 리뷰 1명 필수 + 관리자 bypass | 외형상 엄격 | 매번 bypass라 보호가 형식뿐 | 정직하지 않음 |
| 리뷰 1명 필수, bypass 없음 | 가장 엄격 | 머지 불가 | 운영 불가 |
| 보호 규칙 없음 | 편함 | CI 실패나 비밀 정보 유출이 그대로 main에 들어감 | 보안 |

## 결과

- 모든 변경이 PR과 CI(시크릿 검사, PR 정책, 빌드·테스트)를 통과한다.
- 사람 리뷰어가 없는 만큼 자동 검사와 체크리스트의 질이 중요해진다.
- CI 작업 이름을 바꾸면 룰셋의 필수 검사 이름도 같이 바꿔야 한다. 안 그러면 PR이 영원히 대기한다. `scripts/github/` 설정 스크립트로 관리한다.
