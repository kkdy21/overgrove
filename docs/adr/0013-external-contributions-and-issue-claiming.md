# ADR-0013: 외부 기여 모델과 이슈 선점 정책 — fork PR, 5시간 선점 기한, PR 선착순

> 상태: Accepted · 날짜: 2026-11-05 · 관련: #129, [ADR-0012](0012-solo-maintainer-merge-policy.md), [process/collaboration.md](../process/collaboration.md)

## 맥락

메인테이너는 Claude Code 같은 AI 에이전트를 쓰는 협업자들을 모아 이슈 단위로 개발을 맡길 계획이다. 이때 다음 문제가 생긴다.

- 여러 사람이나 AI가 **같은 이슈를 동시에 개발**한다. 토큰과 리뷰 시간이 중복으로 든다.
- 이슈를 **가져가 놓고 방치**한다. 다른 사람이 그 이슈를 시작하지 못한다.
- 협업자에게 저장소 쓰기 권한을 주면, 현재 룰셋(승인 0, ADR-0012) 아래에서 **자기 PR을 리뷰 없이 머지**할 수 있다.
- 메인테이너가 모든 PR을 직접 검수하기는 어렵다. 검수에도 AI를 쓴다.

AI 에이전트 기준으로 이슈 하나는 대개 몇 시간 안에 PR까지 간다(메인테이너 판단).

## 결정

### 1. 기여 모델: 일반 오픈소스 방식
- 협업자는 **자기 fork에서 PR**을 올린다. 저장소 역할(Write, Triage)은 주지 않는다.
- **머지는 메인테이너만 한다.** 협업자는 머지 권한이 없으므로 승인 0 룰셋(ADR-0012)을 그대로 둔다.
- 메인테이너는 Claude Code 스킬 `/pr-review`로 AI 검수(범위, 보안, 테스트, 선점)를 하고, 확인한 뒤 squash 머지한다.
- 외부 기여자 PR의 워크플로우 실행 승인은 **첫 기여자만** 요구한다(`first_time_contributors`). 우리 워크플로우는 fork PR에 쓰기 토큰이나 비밀 값을 주지 않으므로 반복 승인의 실익이 작다.

### 2. 이슈 선점(claim)
| 규칙 | 값 |
|---|---|
| 선점 방법 | 이슈에 `/claim` 댓글 → 봇이 담당자로 지정 (`issue-claim.yml`) |
| 해제 방법 | `/unclaim` 댓글, 또는 자동 만료 |
| 선점 기한 | **5시간.** 선점 후 5시간 안에 `Closes #n`이 들어간 PR(Draft 가능)이 없으면 자동 해제 (`claim-expiry.yml`, 30분 주기) |
| 유지 조건 | 담당자의 열린 PR이 있는 동안. PR이 머지 없이 닫히면 다음 주기에 해제 |
| 동시 선점 | 1인당 2개 |
| 선점 불가 | Epic, `status:blocked`, `status:needs-decision`, `status:triage`, 닫힌 이슈 |
| 담당자 없는 이슈 | **PR 선착순.** 먼저 열린 PR의 작성자를 담당자로 지정한다(GitHub이 허용하는 경우) |
| 강제 | `pr-policy` 검사: 남이 선점한 이슈의 PR, 또는 담당자 없는 이슈에 이미 먼저 열린 PR이 있는 경우 실패 |
| 메인테이너 | 선점 기한과 `pr-policy` 선점 검사에서 면제 |

## 대안

| 대안 | 기각 이유 |
|---|---|
| 순수 PR 선착순(선점 없음) | 가장 단순하지만, AI들이 같은 이슈를 동시에 개발해 토큰과 리뷰 시간이 중복으로 든다 |
| 메인테이너가 직접 배정 | 통제는 쉽지만, 배정을 기다리는 동안 협업자가 멈춘다 |
| 협업자에게 Write 권한 + 승인 1명 | 브랜치를 바로 push할 수 있지만 룰셋 변경과 우회 설정이 필요하다. 협업자끼리 서로 승인해 머지할 수 있다 |
| 긴 기한(3–7일) | 사람 중심 오픈소스의 관례지만, AI 개발 속도에서는 방치된 선점이 오래 남는다 |

## 결과

- 장점: 중복 개발과 방치가 자동으로 정리된다. 협업자는 저장소 권한 없이 바로 시작할 수 있다. 머지 권한이 메인테이너 한 명에게만 있다.
- 단점
  - 5시간 안에 Draft PR을 열어야 한다는 부담이 있다. 스킬이 첫 커밋 직후 Draft PR을 열도록 안내해 줄인다.
  - GitHub 스케줄 실행은 지연될 수 있어서 만료가 최대 수십 분 늦을 수 있다.
  - 메인테이너가 머지를 미루면 PR이 쌓인다. squash 머지와 "Update branch"로 협업자의 rebase 부담은 없앤다.

## 후속 작업

- [ ] 실제 운영 데이터로 선점 기한(5시간)과 동시 선점 수(2)를 조정한다. 변경은 이 ADR을 개정한다.
- [ ] 협업자에게 저장소 역할을 주게 되면 ADR-0012를 다시 검토한다(승인 1명 + 메인테이너 PR 경유 우회).
- [ ] 72시간 넘게 활동이 없는 PR의 자동 알림·종료가 필요해지면 `claim-expiry.sh`를 확장한다.
