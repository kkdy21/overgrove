# ADR-0005: 문서 언어는 내부 한국어, 외부 접점 영어로 나눈다

> 상태: Accepted · 날짜: 2026-11-05 · 관련: [docs/README.md §3](../README.md)

## 맥락

메인테이너는 한국어를 선호하고, 기획·설계 문서를 직접 검토해야 한다. 저장소는 공개 오픈소스라 외부 기여자가 처음 만나는 문서와 템플릿의 언어가 기여 장벽을 좌우한다.

## 결정

| 대상 | 언어 |
|---|---|
| `docs/` 전체 (PRD, ADR, 아키텍처, 설계, 테스트, QA, 프로세스), `CLAUDE.md` | 한국어. 기술 용어와 코드 식별자는 영문 그대로 |
| `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md` | 영어 |
| 이슈·PR·Discussion 템플릿 | 영어. 필드 설명에 한국어 병기 |
| **이슈·PR 제목** | **영어**. Conventional 형식 (`feat(git): ...`). 검색성과 squash 커밋 제목 일관성 때문 |
| 이슈·PR·Discussion 본문, 리뷰 코멘트 | 한국어 또는 영어 모두 허용. 외부 기여자가 영어로 쓰면 영어로 답한다 |
| 커밋 메시지 | 영어 Conventional Commits |
| 코드 주석, 테스트 이름 | 영어 |
| 앱 UI 문자열 | v0.1은 영어만. 한국어 현지화는 `later` 범위이며, 도입할 때 String Catalog를 쓴다 |

## 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 전부 한국어 | 검토가 가장 쉬움 | 외부 기여자 진입이 어려움 | 공개 저장소 목적과 충돌 |
| 전부 영어 | 오픈소스 관례에 맞음 | 기획·설계 검토 부담이 큼 | 메인테이너 검토 품질이 떨어짐 |

## 결과

- 메인테이너는 모국어로 설계를 검토하고, 외부인은 영어로 진입한다.
- 외부 기여자가 `docs/`의 설계 근거를 읽으려면 번역이 필요하다. 영어 요약이 필요해지면 `docs/en/` 도입을 검토한다.
- 영어 제목과 한국어 본문이 섞인다. 템플릿 안내 문구로 기대치를 맞춘다.

## 후속 작업

- [ ] CONTRIBUTING에 언어 규칙 명시
- [ ] 이슈·PR 템플릿에 "Title in English" 안내 포함
