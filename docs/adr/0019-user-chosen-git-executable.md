# ADR-0019: 사용자가 고른 git 실행 파일을 믿는 조건

> 상태: Accepted · 날짜: 2026-11-08 · 개정: 2026-11-08 #106 구현 중 group 쓰기 규칙 정정, 보안 검토 반영(검사 대상을 실제 파일과 그 상위 디렉터리로 단순화, 장치·inode 비교, 볼륨 규칙, 보호 디렉터리 읽기) · 관련: #338, #106, #99, #317, ADR-0008, [design/security-review.md](../design/security-review.md) §1.2·T10, [design/screens.md](../design/screens.md) S-08

## 맥락

ADR-0008 §3은 git 실행 파일을 Xcode·CLT의 git으로 정하고, v0.2.0에서 사용자가 절대 경로를 지정할 수 있게 하기로 했다(#106). 그 조건은 "실행 가능 여부와 `git --version` 응답 확인"뿐이었다.

이 기능은 신뢰 경계를 넓힌다. 지금 [security-review.md §1.2](../design/security-review.md)가 믿는 git은 Apple 서명 git뿐이다. 사용자 지정 경로를 허용하면 사용자가 고른 실행 파일도 믿게 된다. git은 모든 조회와 fetch에서 사용자 권한으로 실행되므로, 잘못된 파일을 고르면 그대로 임의 코드 실행이 된다(보호 대상 1).

공격자 모델(§1.3)에는 "사용자를 속여 앱에 저장소를 등록하게 할 수 있다"가 있다. 같은 수법으로 "이 저장소에는 이 git을 쓰라"고 유도할 수 있다. 예를 들어 저장소 안에 넣어 둔 `bin/git`을 고르게 하는 것이다. 버전 문제도 있다. 최소 지원 버전 2.36과 `lazyFetchControlVersion`(2.45.1, #317) 사이의 git은 쓸 수 있지만 partial clone을 fetch하지 못한다.

관련 위협: T10(실행 환경), T5(fetch 중 lazy fetch).

## 결정

사용자가 고른 git은 **경로·소유자·권한·버전 규칙을 모두 통과할 때만** 쓴다. 검사는 고를 때와 매번 git을 찾을 때(앱 실행, 설정 변경) 다시 한다. 통과하지 못하면 **기본 git으로 조용히 바꾸지 않고** 조회를 멈춘 뒤 이유와 `Use Default`를 보여 준다. 코드 서명은 요구하지 않고 정보로만 표시한다.

### 1. 경로

- **절대 경로만 받는다.** 설정 화면의 `Choose…`(`NSOpenPanel`)로 받는다. 입력란은 두지 않는다. 저장은 고른 그대로 한다. 제어 문자가 든 경로는 거부한다.
- **링크를 푼 실제 파일을 검사한다.** `realpath`로 푼 대상이 일반 파일이고 현재 사용자가 실행할 수 있어야 한다. 예: Homebrew의 `/opt/homebrew/bin/git`은 `Cellar/…/bin/git`으로 풀린다. 화면에는 입력한 경로와 실제 경로를 함께 보여 준다.
- **실행하는 것은 링크를 다 푼 실제 파일이고, 규칙도 그 파일과 그 상위 디렉터리에만 적용한다.** 입력 경로나 중간 링크가 거치는 디렉터리는 판단하지 않는다. 검사 뒤 링크를 바꿔도 이미 만든 클라이언트는 검사한 실제 파일을 실행한다. 다음에 git을 찾을 때는 새 대상을 처음부터 다시 검사한다.
- **등록된 저장소 안의 경로는 거부한다.** 실제 파일의 상위 디렉터리 중 하나라도 다음 위치이면 거부한다. 비교는 문자열이 아니라 장치·inode로 한다. Data 볼륨 firmlink 경로처럼 같은 디렉터리의 다른 이름으로 우회하지 못하게 하기 위해서다(`realpath`는 firmlink를 풀지 않는다). 기준은 검사하는 시점의 등록 목록이다. 나중에 그 경로를 포함하는 저장소를 등록하면, 다음에 git을 찾을 때 거부된다.
  - 등록된 저장소의 최상위 디렉터리
  - 공통 git 디렉터리
  - 알려진 워크트리
- **xcrun shim은 기본값으로 처리한다.** 실제 경로가 `/usr/bin/git`이면 기본값으로 다룬다. 이 shim은 호출당 약 8ms가 들고, 개발 도구가 없으면 설치 대화상자를 띄운다(ADR-0008 후속 작업). Xcode·CLT 디렉터리 안의 git을 직접 고르는 것은 일반 경로로 다룬다.

### 2. 소유자와 권한

- 실제 파일과 그 상위 디렉터리 전부는 **root 또는 현재 사용자 소유**여야 하고, **root·소유자가 아닌 계정이 쓸 수 없어야** 한다. ssh `StrictModes`와 같은 생각이다.
  - **other 쓰기는 항상 거부한다.**
  - **group 쓰기는 그룹이 `admin`(gid 80) 또는 `wheel`(gid 0)일 때만 허용한다.** `admin` 구성원은 sudo로 root가 될 수 있는 계정이라, 이 그룹의 쓰기 권한은 root 소유와 같은 신뢰 수준이다. macOS는 `/Applications`를 `root:admin` 0775로 두고, Homebrew의 `Cellar`는 `<사용자>:admin` 0775다. 이 예외가 없으면 Xcode와 Homebrew의 git이 모두 거부된다(#106 구현 중 실측).
  - `staff`(gid 20) 같은 일반 그룹의 쓰기는 거부한다.
  - sticky 비트가 있는 공용 쓰기 디렉터리(`/tmp` 등)도 거부한다.
- 위 규칙은 실제 파일과 그 상위 디렉터리 전부(`/`까지)에 적용한다.
- **실제 파일이 소유권을 무시하는 볼륨(`MNT_IGNORE_OWNERSHIP`)이나 로컬이 아닌 볼륨에 있으면 거부한다.** mode 비트가 아무것도 증명하지 못하기 때문이다.
- **코드 서명은 요구하지 않는다.** Homebrew git은 ad-hoc 서명이라 서명 유무로 구분이 안 된다.
  - 설정 화면에 실제 경로와 함께 `Apple-signed` 또는 `Not signed by Apple` 정보만 보여 준다. 경고 대화상자는 없다.
  - 판정은 Security 프레임워크의 정적 코드 검사(`anchor apple`)로 하고, 프로세스를 실행하지 않는다.

### 3. 버전

- `git version`은 기존 `GitEnvironment.discover`와 같은 인자, 환경 allowlist, 타임아웃으로 실행한다(ADR-0008 §6–7).
- **2.36 미만은 거부한다.** 기존 `GitVersion.isSupported` 규칙이다.
- **`lazyFetchControlVersion`(2.45.1) 미만은 허용하되 안내한다.** 설정 화면에 "이 git으로는 partial clone 저장소를 fetch할 수 없다(2.45.1 이상 필요)"를 보여 준다. 백포트된 2.39.4–2.44.x도 버전 비교라 같은 안내가 나온다. 안전한 쪽이다(#317).

### 4. 검사 시점과 실패할 때

- **고를 때** 1–3을 검사하고, 통과하지 못하면 저장하지 않는다.
- **git을 찾을 때마다** 1–3을 다시 검사한다. git을 찾는 시점은 앱 실행 후 첫 사용과 설정 변경 직후다. 저장된 값은 같은 계정의 다른 프로세스가 바꿀 수 있고(§1.2상 위협 모델 밖), 실행 파일 자체가 바뀔 수도 있기 때문이다.
- **실패하면 fail closed다.**
  - git을 찾는 단계가 오류(사용자 지정 git 거부, 이유 포함)를 내고 조회와 fetch는 실행되지 않는다.
  - Setup Assistant와 설정 화면에 이유와 `Use Default`를 보여 준다.
  - 기본 git으로 조용히 바꾸지 않는다. 사용자가 명시적으로 고른 것을 존중하고, 다른 git으로 돌고 있다는 사실을 숨기지 않기 위해서다.
- **설정을 바꾸면 곧바로 다시 검사한다.** 통과하면 이후 실행부터 새 git을 쓴다. 이미 실행 중인 명령은 이전 git으로 끝난다.

### 보호 디렉터리 목록

- 연결 워크트리 위치는 git을 실행하지 않고 `<공통 git 디렉터리>/worktrees/*/gitdir`에서 읽는다.
- 이 파일은 저장소가 통제한다. 그래서 링크를 따라가지 않고(`O_NOFOLLOW`), 막히지 않게(`O_NONBLOCK`) 열고, 4KB 이하의 일반 파일만 읽는다. 항목 수에도 상한을 둔다. FIFO, 장치로 가는 링크, 큰 파일은 건너뛴다.
- git 2.48+의 상대 경로(`worktree.useRelativePaths`)는 그 항목 디렉터리 기준으로 푼다.
- 이 목록은 거부할 경로를 늘리기만 한다. `/`는 넣지 않는다. 넣으면 모든 git이 거부되기 때문이다.
- **사용자가 git을 고르지 않았으면 이 목록을 계산하지 않는다.** 기본 git 사용자는 이 기능 때문에 저장소 파일을 읽지 않는다.

### 5. 저장

- 키는 `UserDefaults`의 `settings.gitExecutablePath`(문자열)다. 값이 비어 있거나 없으면 기본 git(ADR-0008 §3, `xcode-select -p`)을 쓴다.
- 비샌드박스 앱이라 security-scoped bookmark는 쓰지 않는다. 경로 외의 값(토큰 등)은 저장하지 않는다.

### 6. `GitEnvironment.discover`와 테스트 override

- `discover`는 실행 파일 출처를 입력으로 받는다. 세 가지다.
  - 기본값: `xcode-select` 개발자 디렉터리
  - 사용자 지정 경로: 1–3의 규칙을 검사한다
  - 테스트 전용 주입
- **규칙 검사는 앱 경로에만 적용한다.**
  - 테스트 전용 주입(#99의 `OVERGROVE_TEST_GIT`, 지금은 `developerDirectory:`)은 경로·소유자 규칙을 우회한다. 임시 디렉터리에 빌드한 git(scratchpad, `/tmp`)을 쓸 수 있어야 하기 때문이다.
  - `git version` 확인, 최소 버전 검사, `OVERGROVE_TEST_GIT_VERSION` 대조는 그대로 유지한다.
- 테스트 전용 주입은 앱 코드에서 쓰지 않는다. 앱의 설정 경로는 항상 사용자 지정 경로 출처를 거친다.

### 범위 밖

- 저장소별로 다른 git을 고르는 기능
- PATH 검색이나 Homebrew 경로를 뒤져 git을 자동으로 찾아 제안하는 기능. ADR-0008의 "PATH 검색 기각"은 그대로다.

필요해지면 later 이슈로 다룬다.

## 결과

- Homebrew git이나 직접 빌드한 git을 쓸 수 있다. 신뢰는 "사용자가 골랐고 소유자·권한·버전 규칙을 통과한 실행 파일"까지만 넓어진다.
- 저장소가 자기 안의 실행 파일을 git으로 쓰게 만들 수 없다.
- 같은 계정의 프로세스는 설정값이나 실행 파일을 바꿀 수 있다. 이것은 원래 위협 모델 밖이다(§1.2). 매번 다시 검사하므로 그 경우에도 규칙은 적용된다. 검사와 `posix_spawn` 사이의 바꿔치기(TOCTOU)는 소유자·권한 규칙상 root나 그 사용자만 할 수 있다.
- 오래된 git을 고르면 partial clone fetch가 막힌다는 안내를 보게 된다.
- 고른 git의 신뢰 범위는 실행 파일 하나보다 넓다. 그 git이 쓰는 헬퍼(`libexec/git-core`의 `git-remote-https` 등, fetch 때 실행됨)와, 빌드 때 정해진 system gitconfig(RepoConfigInspector가 system scope로 신뢰함)도 함께 믿게 된다. 이 둘은 소유권 검사 대상이 아니다. Homebrew·Xcode처럼 같은 설치 안에 있으면 같은 소유자 규칙을 따르지만, 이 ADR이 검사하지는 않는다.
- macOS ACL(`chmod +a`)로 다른 계정에 쓰기를 허용한 경우는 mode 비트만으로 알 수 없다. ACL은 소유자만 설정할 수 있으므로 잔여 위험으로 둔다.
- 규칙은 실제 파일만 판단하므로, 저장소나 다른 계정이 중간 링크를 바꿔 보호 영역 밖에 이미 있는 사용자 소유 실행 파일을 가리키게 할 수 있다. 그 파일도 다음 탐색에서 같은 규칙과 `git version` 확인을 통과해야 한다. 그러니 사용자를 속여 그 파일을 직접 고르게 하는 것과 위험이 같다.
- 악성 저장소는 `gitdir`에 특정 디렉터리를 적어, 그 안의 git을 고르지 못하게 할 수 있다(서비스 거부). 안전한 쪽으로 실패하고 `Use Default`로 빠져나갈 수 있다. 다만 메시지는 "등록된 저장소 안"이라고 나온다.
- 다시 검토할 조건:
  - 저장소별 git 요구가 생길 때
  - git이 실행 파일 위치를 바꾸는 배포 방식이 흔해질 때
  - Apple이 CLT git 경로 정책을 바꿀 때
