## 2. 공통 승인 절차

1. Phase Epic의 하위 이슈가 모두 닫혔는지(또는 다음 Phase로 넘겼는지) 확인한다.
2. `/phase-gate`로 보고서를 만든다. 내용: 산출물 표, 자동 점검 결과, 열린 이슈, 보안 체크리스트, 결정 필요 사항.
3. 메인테이너가 승인하면:
   - Phase Epic에 승인 코멘트를 남기고 닫는다.
   - `docs/roadmap.md`와 이 문서의 "현재 상태"를 갱신한다(PR).
   - 해당 Phase 문서의 머리말 상태를 `Proposed` → `Accepted`로 바꾼다.
   - Announcements Discussion에 짧게 공지한다(선택).
4. 반려되면 지적 사항마다 이슈를 만들고 Epic을 연 채로 둔다.

## 4. 승인 기록

### Phase 1·2 게이트 — 2026-11-05

- **승인 방식**: 메인테이너(@kkdy21)가 2026-11-05에 "검토를 따로 하지 않을 테니 자율적으로 진행하라"고 위임했다. 그에 따라 Claude Code가 아래 게이트 점검을 수행했고, 그 결과를 승인으로 기록한다. 메인테이너는 언제든 이 결정을 되돌릴 수 있다. 되돌릴 때는 해당 문서를 `Proposed`로 바꾸는 PR을 연다.
- **위임 범위**: 이 위임은 Claude Code가 작성한 기획·설계·프로세스 산출물의 검토에만 해당한다. **협업자가 제출하는 코드의 검수는 그대로 한다.** 협업자 PR은 메인테이너의 Approve 리뷰(`/pr-review`로 AI가 도울 수 있다)를 받은 뒤에만 머지한다([pull-requests.md §4](pull-requests.md#4-머지-정책-adr-0012)).
- **자동 점검**
  - 전체 이력 gitleaks: 누출 없음
  - 금지 API 검사: 통과
  - 픽스처 생성: 통과(워크트리 9개)
  - 상대 링크: 모두 유효
  - 필수 검사: `main`의 모든 PR에서 통과
- **산출물**: 위 §3의 Phase 1·2 항목이 모두 저장소에 있다. 해당 문서의 머리말을 `Accepted (Phase N 게이트, 2026-11-05)`로 바꿨다.
